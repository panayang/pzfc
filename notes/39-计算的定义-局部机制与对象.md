# 39 · 计算的定义：局部机制只看得见对象

> 你提出两个方向：计算的定义（图灵论题及其推广），以及概率过程。本篇先试第一个，它会自然地把第二个带进来。
> 形式化：
> - `lean/Local.lean`：确定性的局部算法，6 条，不用选择；
> - `lean-mathlib/Observe.lean`：看得见什么由值决定；用硬币打破对称，8 条；
> - `lean-mathlib/Views.lean`：在有限系统上，对象恰好是局部计算能分辨的东西，5 条。

## 0. 为什么两个方向在这里是一个

- **机器的分析就是原点处的粘合。** Gandy（1980）分析"机械装置能算什么"时，提出了四条原则（待核验）：
  - 状态是带原子的有限集合，转移在原子的置换下不变；
  - 层级有界；
  - 整体状态由它的有界部分唯一地拼起来；
  - 每个部分的下一步，只取决于它的一个有界邻域。

  结论是：满足这些原则的装置，只能计算图灵可计算的函数。这几条，恰是原点处的 GLU：锐的回答，良基，单个全局上下文，局部数据唯一地粘成整体。
- **推广的方式不同。**
  - 主流的推广换**机器**：预言机、实数机、量子机、无穷时间机。
  - 这里改的是**局部数据怎样粘合**，也就是 π：值、形状、上下文、对称。
- **可计算性变成一个依赖 π 的问题。**
  - 离开原点以后，"哪些 ℕ → ℕ 的函数可算"不会变：保守性把它锁住了。
  - 会变的是：哪些**任务**能由局部的机制完成——在匿名的、对称的、只看得见局部的情形下。
- **概率在这里自然出现。** 确定性的局部机制打不破对称，随机的可以——这正是 `38` 的"随机的选取不需要选择"，换到了动态的情形。

## 1. 局部算法

- 一个**系统**上的每个结点有一个状态。每一轮，每个结点按自己的状态、以及观察到的成员状态，更新自己的状态（`Local.Alg`、`run`）。
- **观察到什么由值决定**（`observe`）：
  - 锐的回答：哪些状态出现在成员中——一个集合；
  - 权重：每个状态出现多少——带计数。
- **结点没有名字**：一开始所有结点处于同一个状态。

## 2. 结果

**(1) 局部算法只看得见对象。**
- 运行与解交换（`run_solves`）。
- 所以，两个结点若是同一个对象，那么无论什么算法、运行多少轮，它们的状态都相同（`run_object`）。
- 这是分布式计算中"视图"（Yamashita–Kameda）的定理，在这里是种类的同一原理的直接推论（待核验）。

**(2) 对称之下选不出领袖。**
- 若一个系统的所有结点都是同一个对象，而且至少有两个结点，那么任何确定性局部算法，在任何一轮都不能让恰好一个结点处于某个状态（`no_leader`）。
- 例：完全系统——每个结点都是每个结点的成员，值都相同（`complete_same`、`complete_no_leader`）。
- 这对应 Angluin（1980）《处理器网络中的局部与全局性质》关于匿名网络的不可能性（待核验）。

**(3) 看得见什么，由值决定。**
- 取 `34` 的例子：结点 a1 以权重 1 含有一个成员，a2 以权重 2 含有同一个成员。
- **只观察集合**时，它们是同一个对象，任何这样的算法都永远分不开它们（`sets_cannot_count`）。
- **观察权重**时，一个只做计数的算法，一轮就分开了它们（`weights_can_count`）。
- 这对应 Hella 等人关于分布式计算的弱模型的结果：接收集合与接收多重集的两种模型，能力不同，分别对应两种模态逻辑（待核验）。在这里，这个区别就是值这个参数。

**(4) 硬币打破对称。**
- n ≥ 2 个匿名结点各掷一枚硬币，共 2ⁿ 种等可能的结果。其中：
  - 只有 2 种让所有结点仍然相同；
  - 恰有 n 种让唯一一个结点掷出正面（`coins_break_symmetry`）。
- 所以随机的局部算法每一轮都以正的概率选出唯一的领袖；重复下去，以概率 1 成功。
- 确定性的算法永远做不到（结果 (2)）。这对应 Itai–Rodeh 的随机领袖选举（待核验）。

**(5) 反方向：对象恰好是局部计算能分辨的东西。**
- 在有限的系统上：两个结点是同一个对象，**当且仅当**每个确定性局部算法，在每一轮都让它们处于相同的状态（`Views.objects_are_what_computation_sees`）。
- 一个算法就够了：每个结点记住它看见的一切，也就是它的**视图**（`viewAlg`、`run_view`）。
  - 视图一轮比一轮细；
  - 在有限的系统上，细化到某一轮就停止（`views_stabilize`）；
  - 停止时的视图，构成一个 Larsen–Skou 互模拟（`35 §3`），于是两个结点是同一个对象（`objects_are_views`）。
- 这对每个值结构都成立：
  - 锐的回答时，算法看见集合，对象是互模拟的类；
  - 带权时，算法看见计数，对象是带权互模拟的类。
- 有限是必要的条件：无穷分叉时，视图处处相同的两个结点，未必互模拟（待核验）。
- 公理剖面：视图的计算不用选择；"细化会停止"的计数，用了经典的可判定性。

**这给了同一原理一个计算的意义**：在有限的系统上，种类中的"同一"，恰好是确定性局部计算的分辨极限——不多，也不少。

## 3. 读法：计算的定义依赖 π

| 参数 | 它决定局部计算的什么 | 本篇的结果 |
|---|---|---|
| 同一（种类的对象） | 确定性局部计算的分辨极限：同一个对象永远分不开；在有限系统上，不同的对象总能分开 | (1)、(5) |
| 对称与名字 | 能否打破对称：没有名字时，对称中的结点分不开 | (2) |
| 值 | 能观察到什么：集合，还是计数 | (3) |
| 值作用在动态上（概率） | 随机性可以打破确定性打不破的对称 | (4) |
| 形状 | 有限的计算，还是无穷的行为 | 尚未做 |
| 上下文（没有全局时钟） | 异步系统中的不可能性 | 尚未做 |

这就是你所说的"不太一定回归主流解读"的推广：
- 丘奇—图灵论题是**原点处的陈述**：有名字、锐的、良基、有全局上下文时，局部机制能算的，恰好是图灵可计算的（Gandy）。
- 离开原点，"计算"分裂成**对 π 可解的任务**。这时的同一原理，恰好给出确定性计算的分辨极限。

**如实说明**：
- (1)–(5) 在分布式计算与模态逻辑中都有对应的已知结果（(5) 对应有限模型上互模拟与模态等价的一致，待核验）。这里新的是**框架**：它们是同一个公理体系的推论——种类的同一、值、对称、权重——而且经典的图灵可计算性是原点。
- "这是丘奇—图灵论题的另一种推广"，目前是一个**假设与研究计划**，不是结论。
