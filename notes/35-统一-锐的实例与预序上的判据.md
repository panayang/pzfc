## 0. 技术：版本统一，模块可以互相引用

- mathlib-free 部分改用与 mathlib 部分相同的 Lean 版本（v4.33.0-rc2），并写成一个没有依赖的 Lake 包（`lean/lakefile.toml`）。
- mathlib 部分通过路径依赖引用它（`lean-mathlib/lakefile.toml`）。
- mathlib 部分的目录从 `lean/mathlib` 改为与 `lean/` 并列的 `lean-mathlib/`。原因：Windows 的文件系统不区分大小写，嵌在 `lean/` 里的 `mathlib` 目录会被当作 `Mathlib` 模块的根，mathlib 的缓存工具因此找错了路径。

于是：
- 通用构造回到了 mathlib-free 部分（`Values`）；
- mathlib 部分只留下 [0, ∞] 的实例，以及值方向上的影子与嵌入（`WeightedKind`，13 条）；
- 不同文件里的构造，可以写定理把它们连起来（§1）。

换版本时只有 `Kinds` 需要修改，共三处 `rw`。新版本在较低的透明度下检查目标，而箭头类型与群元素、`PLift` 只在默认透明度下相等。改用项证明后，数学内容没有变。

## 1. 锐的实例就是形状的拓展

`Shapes` §8 把反基础宇宙构造成"带基点的图按互模拟认同"；`Values` 对每个完备的值结构，把种类构造成"带基点的系统按有共同的像认同"。

在锐的回答处，二者一致：
- 有一个双射 `toUA`，其逆为 `fromUA`（`from_to`、`to_from`）；
- 它把系统的解送到同一个图的解（`toUA_dec`）；
- 它保持并反映隶属（`mem_iff`）。

所以"`Shapes` §8 是一个构造的特例"现在是一条定理，不再只是"二者都是终对象"的推论（`34 §3`）。

三个已构造的种类，关系如下：

| 种类 | 参数 π | 与"一个构造"的关系 |
|---|---|---|
| `Shapes.UA` | （锐，一切，单点） | `Values.UV sharp`，由 `Instances` 证明 |
| `WeightedKind` 的带权种类 | （权重，一切，单点） | `Values.UV weights` |
| `Kinds.U` | （锐与名字，一切，任意小范畴） | 另一个构造，尚未与 `Values` 合并 |

## 2. 预序上的判据

问题（`32 §4`）：对哪些上下文结构，"一个整体的对象在每个上下文里都有成员"总能推出"它有整体的成员"？

对预序，答案是：

> **当且仅当每个上下文下面都有一个根，并且根沿箭头不变**（`Kinds.criterion`）。

这里"根"的写法是：有一个映射 ρ，ρ(c) 在 c 之下，而且 c 可以细化到 d 时，ρ(c) = ρ(d)。等价地说，每个连通分支都有一个最小的上下文；在每个分支里取定一个，就是 ρ。

**充分性**（`roots_glue`，用选择）：
- 在每个根上选一个成员，再沿箭头搬到各处；
- 根沿箭头不变，所以搬过去的结果彼此相容。

两个特例：
- 只有一个根时，不需要选择（`rooted_glue`）；
- 上下文互不相交时，根就是上下文本身（`discrete_glue`）。

**必要性**（`roots_of_glue`，不用选择）：
- 取一个对象：在上下文 c 里，它的成员是以 c 之下的上下文命名的原子（`critObj`）。它在每个上下文里都有成员（`critObj_inhabited`）。
- 若它有整体的成员，这个成员的名字沿箭头不变，而且总在所在的上下文之下；于是名字本身就给出了根。
- 根是从名字里读出来的，所以不用选择。

**读法。**
- `25 §5` 的读法——"选择在失去全局上下文之后能保留多少，取决于局部的选择能否沿上下文结构粘起来"——在预序上有了精确的答案。
- 局部的存在总能粘成整体的，恰好当每个连通分支都有一个全局的上下文（它的最小元）。
- 选择只在各分支之间起作用：
  - 分支内部，根就是全局上下文，存在在那里就是整体的；
  - 分支之间，没有什么需要一致，选择恰好够用。
- 必要性的证明用到了名字（原子）：根是从名字里读出来的。这与 `30` 一致——名字让"是哪一个"成为可以读出的东西。

## 3. 同一的关系形式，对每个值结构

`34 §7` 第 1 条问：带权种类的同一，能否写成关系形式（Larsen–Skou 的概率互模拟）？答案对每个完备的值结构都成立（`Values.same_iff_ls`）：

> 两个结点是同一个对象，当且仅当有一个 Larsen–Skou 互模拟联系它们。

这里的互模拟，是两个系统的结点上的一个**等价关系**：相关的结点，给每一个等价类的聚合值都相同（`LSBisim`）。

- **从共同的像到互模拟**：取"像相同"作为等价关系。一个结点给某个类的聚合值，就是它的像在共同的像中给那个类的像的值（`classVal_img`）。
- **从互模拟到共同的像**：按这个等价关系取商。类的聚合值与代表的选取无关（`classVal_congr`），于是商本身就是一个共同的像。

在锐的回答处，这就是通常的互模拟（`sharp_same_iff`）。

用等价关系，而不是任意关系，是关键。因此这里不需要 `34 §7` 所说的"权重的幺半群是正的、可细分的"：那个条件只在用任意关系作互模拟时才需要。

## 4. 开放

1. **三个参数一起的构造**（第十九轮：在预序上，把上下文放进值里即可，见 `36`；完整的组合仍开放）：把 `Kinds`（上下文与名字）与 `Values`（任意的值）合并。
   - 设计问题是：带权的回答沿细化怎样变化？
   - 锐的情形是"隶属沿箭头保持"；带权时，没有现成的对应。
2. **一般小范畴上的判据**（第二十一轮：已对任意上下文结构证明，`Kinds.criterion_general`；有对称时只有平凡的群满足，见 `38 §2`）：有对称时，障碍不同——Russell 的袜子没有被对称固定的成员（`30`）。预序的答案不能直接推广。
3. **只对纯的对象，判据是否相同？** 必要性的证明用到了名字；没有名字时，是否仍然每个没有根的分支都有反例，还不知道。
4. **上下文性**：在成圈的上下文上，相容的局部数据粘不起来。
